# P0 tech spikes — status

| Spike | Status | Outcome |
|---|---|---|
| ORM + RLS | **Done** | Drizzle works on the RLS-scoped transaction client. Decision and gotchas: `docs/adr/0002-orm-drizzle.md`. Proof: `apps/api/test/spike-drizzle-rls.e2e-spec.ts`. |
| Printer bridge (ESC/POS) | **Software done, hardware NOT validated** | `packages/printer`: ESC/POS builder (text, alignment, bold, size, QR, cut, cash-drawer pulse), ordered print spooler with retry/backoff and dead-letter queue, LAN transport (TCP 9100). Tested against a fake TCP printer only. **Still needed:** run the same bytes on 2+ real printers (58 mm and 80 mm, one LAN and one Bluetooth), confirm cut/drawer/QR behaviour per model, find a way to print the rupee sign (raster/image or model-specific code page — currently printed as `Rs.`), and build the Bluetooth/USB transport inside the React Native app. |
| POS framework (React Native + op-sqlite) | **Scaffolded; native validation pending** | `apps/pos` provides registered-device login, an atomic local demo-order/outbox write, manual batched push, and transactional master-change pull. op-sqlite and SecureStore require an Expo development build. Android SDK/emulator and a test tablet are not available here, so native behavior and the 300 ms local-write target remain unverified. Catalog-backed POS workflows and conflict/reconciliation actions remain outstanding. |
| Offline sync client + server | **Initial client slice implemented** | Device-bound push, per-device sequence deduplication, manual inbox disposition, and a commit-ordered change cursor are implemented. The client preserves rejected events and stores master-data changes but deliberately does not project uploaded events into live orders/payments. See `docs/offline-sync.md` for remaining work. |
